# 应龙平台模型纳管规范

版本：V1.0  
适用范围：申请在应龙大模型推理平台部署、运行和维护的非主线模型。

## 1. 纳管原则

1. 优先复用平台主线模型。仅当主线模型无法满足业务场景时，申请非主线模型纳管。
2. 模型来源、权重授权和使用许可必须清晰、合法且可追溯。
3. 业务方对模型选型、效果验证、交付物完整性及纳管后的持续维护负责。
4. 资源规格应与实际负载匹配，避免长期闲置或超额占用。

## 2. 必备交付物

- 模型基础信息：名称、版本、来源、许可证及适用场景。
- 模型权重：完整、可校验，并附校验信息。
- 部署镜像：固定版本标签，可在平台运行环境中复现。
- 启动配置：Kubernetes YAML、环境变量和依赖说明。
- 接口文档：请求参数、返回结构、鉴权方式和错误码。
- 验证材料：效果测试、性能测试、资源评估和测试样例。

## 3. 验收要求

- 能按交付说明完成部署、启动、停止和健康检查。
- 接口行为与文档一致，关键业务样例验证通过。
- 明确单实例显存、吞吐、并发和延迟基线。
- 无高危安全漏洞，模型和镜像来源可追溯。
- 明确业务负责人、技术负责人和故障响应方式。

## 4. 责任边界

- 平台方：提供资源申请、权限开通、基础运行环境和通用监控能力。
- 业务方：负责非主线模型的部署、配置、升级、调优、故障处置和下线。

## 5. 变更与退出

模型版本、镜像、接口或资源规格发生重大变更时，应重新验证并更新纳管材料。停止使用后，业务方应及时申请释放资源并完成数据与访问权限清理。
